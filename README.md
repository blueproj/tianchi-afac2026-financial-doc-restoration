## 📌 赛题简介

金融行业沉淀了海量核心业务文档（保险条款、费率表、现金价值表等），版式非标、内容密度高、结构复杂（多级标题、嵌套表格、多栏排版、跨页图表）。本赛题要求基于主办方提供的多模态底座 **FinixDoc-VL** 与工具链，构建一套具备**感知、切块、重组、去重与纠错**能力的多模态文档解析工作流，对**超长或超大金融文档截图**自动解析并输出与原文严格对应的高保真 Markdown。

- **输出格式**：标准 CSV（UTF-8），仅两列 `file_name` / `ground_truth`（Markdown 结构化字符串），行数与测试集图片数一致。
- **四大目标**：内容完备性（100% 覆盖、严禁漏检与幻觉）／结构高保真（多级标题、列表、标准 Markdown 表格）／阅读流顺序（多栏、跨块）／工程鲁棒性（密集表格、超长文档）。
- **模型约束**：线上仅允许调用主办方 **FinixDoc-VL** API；可集成不依赖 GPU、总参数量 **< 10M** 的本地轻量模型；严禁其它第三方大模型 API（穿透式审计）。
- **工程约束**：复现运行时间 **≤ 3h**，一键脚本，Python + 中文注释。

## 💡 方案架构

### 整体流程

```
                        输入图片
                           │
          ┌────────────────┴────────────────
          │ 表格类                           │ 长文档类
          ▼                                 ▼
┌─ Level1 区域切分 ──────────┐   ┌─ 长文档切块 ────────────┐
│ 整页→text/table 区域       │   │ 双栏检测/目录整块/空白带 │
└──────────┬────────────────┘   └────────────┬───────────┘
┌─ Level1.5 子表切分 ────────┐                │
│ 阶梯表按右缘reset拆子表    │                │
└──────────────────────────┘                │
┌─ Level2 表格切块 ──────────                │
│ 行列分析→画线→行带×列组     │                │
└──────────────────────────┘                │
           ▼                                 ▼
┌────── FinixDoc-VL API 并发调用（重试/限流/MD5缓存）──────┐
           ▼                                 ▼
┌─ 反应式纠错重调 ───────────   ┌─ 纵向合并 ─────────────┐
├─ banner 表头分离重建 ──────┤   ├─ 标题层级归一化 ───────┤
├─ 合并 + 文档级后处理 ──────┤   └────────────┬───────────┘
           └────────────┬────────────────────┘
                        ▼
              submission CSV（file_name, ground_truth）
```

### 核心技术创新

#### 1. 三级结构感知切分 + 输入调制
不依赖固定像素，按**行列结构**切块：Level1 区域切分（文本/表格分离、假表格降级）→ Level1.5 子表切分（阶梯表右缘 reset）→ Level2 行带×列组切块（每块 ≤12行×12列、单边 ≤3000px）。配合输入调制：无边框/半边框表**画网格线补结构线索**、短边 <80px **2x 放大防幻觉**，把每块送进模型稳定工作区。

#### 2. 行列先验（贯穿地基）
切块时把每个 chunk 的**行列范围编码进文件名**（如 `chunk_007_r13-24_c13-24`）。合并时按先验对齐；检测时"返回 10 列而先验说 12 列"即知出错。最初只为调试，后成为全部自动纠错的地基。

#### 3. 反应式纠错重调（模型无关自愈框架）
对 API 返回做四类症状检测（过读/漏列/漏行/纯文本退化），触发后**切半重调**，并以整齐度打分门控——**严格更优才采纳**。B榜 **160 次触发、0 劣化**。

#### 4. banner 表头分离重建
跨列总表头（如"保单年度末"横跨 46 列）在中段列组为空行，模型丢空行导致整列数据上移（"安静的错误"）。将表头带与主体**上下分离识别 + 程序化重建 rowspan/colspan**，7 张 banner 表全对齐，单版 TEDS **+4.04**。

#### 5. 长文档：双栏/跨页/标题层级
双栏目录**整块送**保阅读序 + 双重门控防误判；切分点**表格避让**保证跨块表格完整；标题层级按编号模式 + 点号深度 **GT 重标定**（封顶 L3）。阅读序编辑距离 **0.008**。

## 🚀 快速开始

### 环境准备

```bash
bash setup_env.sh     # 创建 conda 环境 afac2026 并安装依赖
```

### 运行

```bash
# 方式一：使用缓存（默认，约 3~10 分钟，逐字节复现）
bash run.sh

# 方式二：不用缓存，全部真实调用 API（需 FinixDoc-VL 开放，约 1.5 小时）
rm -rf cache/ && bash run.sh
```

## ⚠️ 注意事项

- **合规**：全工程唯一模型调用为官方 FinixDoc-VL API（`api_client.py`），无本地模型、无 Prompt 工程（接口无 prompt 参数）、CPU-only。
- **缓存 ≠ 硬编码**：`cache/` 内每个文件是一次 API 调用的原始返回文本，文件名为该 chunk 图片的内容 MD5；删除缓存后重新运行即全部真实调用。
- **解压提示**：数据图含中文文件名，老版本 `unzip` 可能报 `File name too long`，请用 `LANG=C.UTF-8 unzip xxx.zip` 或 Python `zipfile` 解压。
- **内存要求** ≥ 8GB（最大单表 22928×16223 ≈ 372MP）。
