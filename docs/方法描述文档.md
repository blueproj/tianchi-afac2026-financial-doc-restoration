## 1. 方案概述

本方案是一套**纯工程化**的复杂金融文档解析流水线：以官方 FinixDoc-VL API 为唯一识别引擎，围绕它构建「图像结构分析 → 智能切块 → 并发识别 → 反应式纠错 → 结构化合并 → 规则后处理」的完整闭环。除 API 调用外，全部为 CPU 图像处理与规则逻辑，**不依赖任何额外模型，也没有任何本地模型权重**。

我们的核心认识只有一句话，也是整个方案的设计原点：

> **FinixDoc-VL 的能力边界是稳定、可测的。工程要做的，是把输入"调制"到它的稳定工作区——该切的切、该放大的放大、该补结构线索的补；再把碎片无损地拼回去；拼错的地方，要能自己发现、自己纠正。**

围绕这一认识，方案在 B 榜取得 overall 93.876479、table_TEDS 86.1149 的成绩。

### 1.1 预估推理时间与推理资源

| 项目 | 说明 |
|---|---|
| 硬件 | 普通 CPU 机器即可（**无 GPU 依赖**），内存 ≥ 8GB，磁盘 ≥ 3GB |
| 模型 | 仅 FinixDoc-VL API，**无任何本地模型/权重文件** |
| 软件依赖 | Python 3.11 + requests / numpy / Pillow / opencv-python（均纯 CPU） |
| API 调用量 | B 榜 100 张全量 ≈ 7000 次（含自动纠错的二次调用） |
| **推理耗时（真实调 API）** | **约 1.5 小时**（B 榜首次全量跑实测 5566 秒，缓存为空、并发 16 路），远低于 3h 上限 |
| **推理耗时（用随包响应缓存）** | **约 3~10 分钟**（实测 216 秒），可逐字节复现 B 榜提交结果 |

## 2. 赛题背景与问题分析

### 2.1 官方 baseline 与它的天花板

赛题的起点是主办方直播答疑时给出的思路：**按直方图投影做切分**——对整图做行方向像素投影，在空白带处切成若干条，逐条送 API，再把文本拼起来。主办方预估这种做法能到 A 榜 65 分左右。

我们第一时间复现了它，实测与官方预估基本一致。这条路线验证了"切块 + 拼接"可行，但把它的输出逐样本看过之后，我们发现它有三个结构性缺陷——这三个缺陷，基本定义了我们后面一个月的全部工作：

1. **切分不感知结构**：投影只认"空白"、不认"语义"，表格会被从行中间切断、表头与数据被分家、双栏目录被横向切穿；
2. **拼接不感知结构**：纯文本首尾相接，表格行列对不齐，跨块的表格直接碎掉；
3. **对模型输出无条件信任**：漏行、漏列、幻觉、截断全部照单全收，没有任何检测与纠正机制。

### 2.2 难点量化：能力边界是可测的，而且不只一个方向

把失败样本逐个 chunk 排查之后，我们发现 VLM 的失败并不是随机的，而是集中在**三个可描述、可复现的方向**上——每个方向都有明确的触发条件和典型征候：

| 边界方向 | 典型征候（实测） | 对应手段 |
|---|---|---|
| **图太大 / 内容太多** | 密集费率表 GT 十万字级，整图直提时输出被长度上限截断，回来的内容严重不完整 | 按行列结构切块，每块 **≤12行×12列**、单边 ≤3000px（§4.1） |
| **图太小** | 89×26px 的"投保年龄"裁片 → 返回凭空幻觉的人名"陈泽华"；全量扫描 122 个小文字区域，幻觉样本短边**均 ≤41px**，而 ≤80px 的全部正确 | 短边 <80px 先 2x 放大（§4.1） |
| **内容太均质 / 缺结构锚点** | 无表头无标签列的纯数字矩阵（期望 12行11列）→ 模型返回 **1024 行**、且只有 **49 个不重复值**，退化为一维数字流与无限循环 | 无边框/半边框表先画网格线补结构线索（§4.1）；退化检测 + 切半重调（§4.2） |

这张表就是 §1 那条认识的直接依据：**模型的失败模式可枚举、可预防**。因此我们不去"期待模型变好"，而是针对每个方向做对应的输入调制（§4.1），并在残余失败上加一层检测与自愈（§4.2、§4.3）。后文所有技术点，都可以按这张表对号入座。

### 3.2 一个贯穿全局的设计：行列先验

Level2 切块时，**每个 chunk 的行列范围会直接编码进文件名**（如 `chunk_007_r13-24_c13-24` = 第 13~24 行、第 13~24 列）。这个"行列先验"是后面一切自动纠错的地基——当 API 返回 10 列、而先验说应该有 12 列时，程序立刻就知道出了问题。它最初只是为了调试方便，最后却成了整个方案最关键的基础设施。

### 3.3 四个技术模块与三个缺陷的对应

针对 §2.1 的三个缺陷，方案给出对应的解法，即本文 §4 的四个模块：

| 缺陷（§2.1） | 对应技术（§4） | 一句话 |
|---|---|---|
| ① 切分不感知结构 | 4.1 输入调制 | 三级切分 + 画线补结构 + 小图放大，把每一块送进模型稳定区 |
| ③ 对模型输出无条件信任 | 4.2 反应式纠错重调 | 用行列先验检测症状，切半重调、更优才采纳 |

## 4. 表格链路关键技术

表格（尤其 100+ 行 × 50~100 列的现金价值大表）是本赛题最大的失分点，也是本方案创新最集中的地方。

### 4.1 输入调制：把每一块送进模型的稳定区

这一步的目标不是"把图切小"，而是**把送给模型的每一张图都调到它能稳定处理的形态**——尺寸不能超过输出上限、不能小到让模型幻觉、结构线索要足够清楚。具体四类操作：

**（1）三级切分（控尺寸 + 不切破语义）**

- **Level1 区域切分**：先把整页按空白带切成文字区和表格区。
- **Level1.5 子表切分**：处理阶梯表。一张 region 里纵向堆了好几段"表头 + 阶梯数据"（男性块/女性块），检测信号是"每行内容右缘先缩到底、再跳回满宽"，在 reset 点切开，各自识别完再合回一个 `<table>`。
- **Level2 行列切块**：检测行/列边界，按"行带 × 列组"二维切块，切点只落在行列间隙；每块行列范围写入文件名（§3.2 的行列先验）。

**（2）画线：主动补充结构线索**

对**无边框表（borderless）与半边框表（semi_bordered）先把缺失的网格线补上再切**（全边框表无需处理）——同一块图，有线和无线送给 VLM，行列对齐的稳定性差别非常大。

![画线前后对比（样本 a4e24107）](assets/gridline_before_after.jpg)

*上：原图完全无线，列与列仅靠空白分隔，数值又高度相似（同一行多个 3912.7），模型很容易数错列；下：补画网格线后送入，行列边界变成显式信号。这一块的画线使竖线从 0 增至 12 条。*

画线有两个保护原则（两类表各有一个专用画线器：`_draw_borderless_grid_lines` / `_draw_bounds_grid_lines`）：
- *表头词保护*：竖线若落在按字间距聚合的表头词内部就不画，否则「保单年度末」会被字缝切开；
- *切内容过滤*：画完检查每条竖线两侧 ±5px 是否都贴着暗像素（hug≥2 行则删线），否则「98113.2」会被小数点缝隙切成「98113 | .2」。

**（3）尺度适配：小图 2x 放大防幻觉**

图太小同样会出问题：89×26 像素的"投保年龄"裁片直接送 API，返回的是"陈泽华"——一个凭空幻觉的人名。短边 <80px 先 2x 放大后 100% 正确；密集表格 chunk（每格 <25×15px）同样自动 2x。这类幻觉（随机人名/长串数字/提示词泄漏）在极小图上是系统性的，所有小图直送 VLM 的路径都加了放大兜底。

**（4）纯空 chunk 跳过**

稀疏大表右下角有大量空白块，暗像素占比 <0.02% 直接生成空表、不调 API（省调用，也避免模型对空图复读）。

### 4.2 反应式纠错重调：识别错误可以被检测，也可以被自愈

有了 §3.2 的行列先验，每个 chunk 返回后我们做四类症状检测，命中就自动"切半重调"：

| 症状 | 判据（对原生响应） | 处置 |
|---|---|---|
| 过读 / 行列不齐 | 某行列数 > 期望，或各行极差 ≥ 2 | 沿"按列数居中"的真实竖线切左右两半，各自重调，按行合并 |
| 均匀漏列 | 各行列数一致但 < 期望 | 同上 |
| 均匀漏行 | 返回行数 < 期望 | 沿横线切上下两半，重调后纵向堆叠 |
| 纯文本退化 | 无 `<table>`，且每行数字个数 ≤ 期望列数一半 / 行数远超期望 / 唯一行占比 <0.7 | 左右切半重调（切窄后模型恢复正常） |

这里有两个我们认为值得强调的细节：

**采纳门控**。重调结果必须在整齐度打分（`行间极差×10 + 与期望列数偏差`）上**严格优于**原始结果才被采纳，否则保留原始走兜底补全。这让整个纠错机制变成"只可能变好、不可能变坏"——B 榜全量触发约 160 次重调，没有一例劣化。我们所有自动化修复都遵循这个原则。

**"纯文本退化"是我们踩出来的发现**。有个 chunk 期望 12 行 11 列，API 却返回了 1024 行、每行 1 个数字，且只有 49 个不重复的值——模型在无表头、无标签列的密集数字矩阵上丢失了二维对齐，退化成一维数字流甚至无限循环。这种响应里根本没有 `<tr>` 标签，常规的行列计数判据全部失效（解析出 0 行），错误就这样静默地漏过去了：兜底重建把仅有的 1~2 列数字塞进表格最左边，其余 10 列全空。我们为它专门设计了基于文本形态的判据，命中后切半重调——受影响的 3 个样本各整块恢复了 120+ 个数值。

### 4.3 banner 表头分离重建：根除最隐蔽的整表错位

这是修复前**单项失分最大**的问题：B 榜 80 张多列组表里 26 张（33%）存在跨列 banner 表头，全部整表错位。

以典型样本为例：122 行 × 50 列，首行是 4 个标签列（交费期间/保险期间/性别/年龄，rowspan=2）+「保单年度末」横跨 46 个数据列。

![banner 表头实例（样本 19e95441，仅截取左侧 15 列）](assets/banner_table.jpg)

*图中：蓝框是 4 个标签列（纵向 rowspan=2）；红框是横跨 46 列的 banner 表头「保单年度末」；绿框是它下层的子表头（1..46 列号）。关键在于：**banner 文字只存在于图的最左端**，往右整条 banner 行都是空白。*

按列组切块后，中段列组的顶行是空白（banner 文字不在它那段），VLM 见到全空行就直接丢弃——后面所有数据上移一行。合并时按行索引对齐，第 11~50 列全部错位：18 岁那行拼上的是 19 岁的数据。而错位后的表格**看上去仍然整齐**，不对照原图根本发现不了——这是它最隐蔽也最危险的地方。

我们试过的第一版方案是"给每个表头块都拼上左侧标签列作锚点"，**实验证伪了**：非首组拼标签反而让 VLM 把标签当正文噪声，banner 行照样丢，甚至整体退化成纯文本。最终方案是**表头带与表主体上下分离**：

1. **检测**（双路）：快路看首列组返回的 row0 是否含 `colspan≥2` 的 banner；banner 居中/靠右不在首列组时，裁一条"全宽 × 顶部 2 行"的表头条单独重读兜底。两路都加了**数字守卫**——真 banner 是纯文字标题，候选文字含数字（如"出生满30日"，其实是年龄列头）直接拒绝，防止误触发。
2. **重建**：首组拼标签读出 标签 + banner 文字；其余列组只裁数据列头读子表头数字（纯数字行 VLM 读得很稳）；然后**程序化拼出** `row0=[标签×N(rowspan=2), banner(colspan=数据列总数)], row1=[1..N]`。
3. **主体正常切**：主体里不存在 banner 空行，各列组行数天然一致，错位从根上消除。

实测 7 张 banner 表全部重建正确（colspan=46/46/46/99/99/30/25，子表头 1..N 与 GT 完全一致）。这一项贡献了 v7 版本 table_TEDS +4.04 里的大头。

### 4.4 文档级后处理：让输出结构与 GT 对齐

最后一步全是确定性规则（按 `<table>` 独立作用，不依赖模型）：非 HTML 响应按行列先验重建表格；剔除被内容夹住的全空行列；阶梯表每列的"-"分隔符只留第一个；行×列 <50 的小表转纯文本；空表删除；表尾空行删除；表格上方游离文字并入首格（词数恰等于列数时直接作为表头行）；清洗提示词泄漏；开标签统一为 `<table border="1" cellpadding="8" cellspacing="0">` 对齐 GT。

## 5. 长文档链路关键技术

长文档的难点在切分而不在识别：

- **三段式切分**：能左右分栏的区域是双栏目录区，其上方切不开的是标题区、下方是正文区；
- **目录整块送**：双栏目录不做左右拆分，整块交给 API 按人类阅读顺序输出——我们对比过，拆开再拼的阅读序损失明显大于整块识别。为防长表格被误判成目录，加了"双栏组起始位置 + 左右栏均衡度"双重门控；
- **表格避让**：切分点绕开表格区域，保证表格完整落在单个 chunk 内；
- **标题层级归一化**：对照训练集 GT 重标定的规则——编号标题按点号深度递进（"1."→二级、"1.1"→三级）、层级封顶三级、剔除加粗标记等。

## 6. 工程可靠性与复现

- **内容寻址缓存**：API 响应按 chunk 图片内容 MD5 缓存。
- **并发与容错**：多 userId 轮转、16 路并发、指数退避重试；单 chunk 失败兜底空表，单样本失败不拖垮全局。B 榜正式运行 100/100 成功、7000+ 次调用零失败。
- **全链路可观测**：每个样本落盘切块图、原始响应、后处理响应、合并结果和可视化 report.html。我们每一轮优化都是从这些中间产物里"看"出来的，审核时也可以逐 chunk 核对。

## 7. 实验与迭代历程

### 7.1 三阶段总览

整个方案的演进可以分成三个阶段，对应 §2 认识的逐步落地：

1. **阶段一（复现 baseline）**：复现官方直方图投影思路，确认其 ~65 分天花板，归纳出三个结构性缺陷（§2.1）；
2. **阶段二（A 榜期，架构成型）**：把"盲切盲拼"改造成"结构感知"的分层架构，三个缺陷逐一有了对应解法；
3. **阶段三（B 榜期，精细化攻坚）**：在 3 天评测窗口内迭代 8 个版本，把 table_TEDS 从 65 推到 86。

### 7.2 阶段二：从"盲切"到"结构感知"

针对三个缺陷，A 榜期我们把 baseline 逐步改造成了 §3 的分层架构：

- **切分感知结构**：先做 Level1 区域切分（文字/表格分家）；表格内部用 CV 检测行边界，切点只落在行间隙（告别"切穿数字"）；双栏目录先识别再整块处理；宽表增加列向切分，形成"行带×列组"二维切块，并把行列范围写进文件名（即 §3.2 的行列先验）；
- **拼接感知结构**：表格按行列索引对齐合并而非文本相接；重叠区去重；长文档按阅读序纵向合并；
- **输出规范对齐 GT**：对照训练集 GT 逐条校准标题层级规则、表格标签格式等。

这个阶段同样重要的是**被实验否定的方案**：比如给空单元格填占位符帮模型对齐（后被证实干扰识别，负优化）、给空 banner 行补竖线帮模型"看见"空行（实验证明 VLM 丢弃全空行与有无边框无关）。这些"弯路"帮我们排除了错误方向，把力气收敛到"切分 + 先验 + 纠错"这条主线上。

### 7.4 方法论小结

回头看，有几条方法论贯穿始终：

1. **badcase 驱动，先归因再动手**：每一分都能说清来自哪个样本的哪类错误——切分错、模型错、合并错还是后处理错，从不盲调参数。
2. **先做最小实验验证假设，再写工程代码**：banner 方案里"拼标签列"的设想就是被 20 分钟的小实验证伪的，避免了一次方向性返工。
3. **一切自动修复都要过"更优才采纳"的门**：纠错机制本身不能引入新错误，这保证了八个版本里只有 v6 一次回退，且当天定位当天修复。
4. **负优化及时砍**：占位填充、补竖线救空行、全量标签列分离，都是实验否定后果断放弃的方案——它们的价值是把我们推向了正确的方向。

## 9. 总结与展望

### 9.1 Ensemble 说明

本方案**未使用任何 ensemble**：单一确定性流水线 + 单一官方 API，表格/长文档两条链路是按文档类型路由，不是模型集成。

### 9.2 核心取舍

我们最核心的取舍是：**把 VLM 当作"受约束的 OCR 原语"，而不是端到端黑盒**——即只让它做"看清一小块图上的字"这一件最基础的事，像调用一个函数那样使用；不指望它理解版面、不指望它自己拼表格、不指望它判断哪里错了。所有结构性智能——怎么调制输入、怎么对齐、怎么重建、怎么发现并纠正错误——都放在可控、可解释的程序侧。

这带来三个直接收益：
- **可调试**：每个错误都能定位到具体哪个 chunk、哪个环节；
- **可复现**：逐字节一致（见 §6）；
- **可迁移**：方案里那批阈值（单块 ≤12×12、小图放大阈值 80px、退化判据等）本质上就是对"当前这个 VLM 能力边界"的量化描述。若换成另一个 VLM，**只需用几个小实验重新测定这几个阈值，框架（切分 → 行列先验 → 症状检测 → 门控采纳）本身无需改动**。

### 9.3 反思：重心偏了——只盯结构，低估了内容

回头看整个解题过程，我们**方向找对了一半**：很早就定位到赛题的重点与难点在超大表格识别，并把绝大部分精力投入到这里。但重心偏了：

> 我们把几乎所有注意力都放在了**表格结构的恢复**（行列对齐、跨列表头、漏行漏列、幻影行列……），却**低估了表格内容准确率对得分的影响**。

赛后我们重新逐样本过了一遍产出结果，发现不少表格**结构已经恢复得很好、但单元格内的数字错得不少**——这很可能是我们最大的残余失分点。对应到工程上，我们少做了关键的一步：**没有系统探索图像预处理方案去提升送入 API 的图片清晰度**。现有的输入处理只做了 LANCZOS 插值放大，而且：
- 插值放大**并不增加信息量**，只是把模糊的笔画放大；
- 触发阈值（每格 <25px 宽或 <15px 高）还偏保守——全量统计发现，触发放大的有 1939 个 chunk，而**未触发、但行高仅 15~22px 的还有 2035 个**（如每格 44×15px），这批字符仍偏小却没被任何增强就直接送进了模型。

这个反思也提醒我们：评测指标（TEDS）同时考察结构与内容，而**结构错误容易被看见（整表错位一眼就能发现）、内容错误却很隐蔽**（一个数字认错，不看原图根本发现不了）。下一次我们会在迭代早期就建立针对内容准确率的抽样核对机制，而不是只盯结构指标。

### 9.4 未来方向

**① 首要方向：图像预处理——提升内容识别准确率**（对应 §9.3 的反思）
系统探索送 API 前的图像增强管道：锐化（非锐化掩膜）、对比度调节（CLAHE 限制对比度自适应直方图均衡）、去 JPEG 压缩伪影、自适应二值化；同时放宽放大阈值让那 2035 个边缘 chunk 也得到处理。进一步可引入参数量仅几十万的轻量超分模型（如 ESPCN/FSRCNN 类，远低于 10M 合规上限且纯 CPU 可跑）——学习式超分才能真正恢复笔画细节。配套地，需要先建立**内容准确率的评估手段**（抽样人工核对 + 业务先验校验，如同列单调性、行间差分平滑度），才能量化每一步增强的收益。

**② 继续优化表格结构恢复**
当前结构恢复已经做得不错，但仍有缺陷：行列检测本身的过分割/欠分割仍会带来系统偏差（可用 <10M 的轻量表格线检测模型替代纯规则）；行列先验还能支撑更细粒度的"单列组级"重调（当前只做到对半切）；反应式纠错框架（症状检测 + 切分重试 + 门控采纳）也可推广到印章、手写等其他退化形态。

**③ 长文档：标题层级恢复**
长文档的得分大头在阅读序与文本结构，而标题层级是其中最难也最值得探索的一环。当前靠的是对照训练集 GT 校准的规则（编号深度递进、封顶三级等），本质上是经验式的；后续可结合版面特征（字号、粗细、缩进、行间距）与文档层级结构建模，把标题层级从"规则猜"变成"结构推断"。
